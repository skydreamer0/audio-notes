# 啟動設定、錯誤分類與失敗重試 SPEC

狀態：待實作。基線：`48a0bcad14373728e24955264bc5ceddd4981622`。本文定義預期行為，不代表功能已完成。

## 目標與範圍

使用者能在啟動後知道本機 bridge 是否已配置、遇到問題時知道可採取的行動，並在失敗後明確選擇是否再次送出相同音檔。涵蓋桌面設定、bridge 請求與錄音或匯入音檔的生命週期。沿用既有非官方上游、同意視窗、單一轉錄及匯入限制。此項不包含安裝程式、開機自動啟動、server 自動啟動、上游登入管理、背景佇列或跨重啟復原。

## 基線事實

- `CodexAsrRecognitionEngine` 建構時讀取環境變數，轉錄時才檢查 URL。URL 只接受 HTTP literal loopback、指定路徑，且無 userinfo、query、fragment。停用 proxy 和 redirect。key 由環境變數提供。
- `AppConfig` 存放介面設定；讀取失敗時回退預設值。現有 README 要求使用者自行啟動 server，且每次雲端轉錄前明確同意。
- HTTP 401 和 403 現在都顯示為上游登入失效，但回應不一定足以判定失敗位置。現有 adapter 不自動重試；逾時為五分鐘。
- 錄音檔屬於程式暫存，匯入檔屬於使用者。`WavAudioRecorder` 有舊檔清理及 dispose 刪除行為，實作重試時須協調其生命週期。

## 啟動與設定

1. 應用程式啟動時檢查本行程的 `AUDIO_CODEX_ASR_URL` 與 `AUDIO_CODEX_ASR_KEY`。不把 key 寫入設定檔、日誌、命令列、UI、遙測或錯誤文字。無 key 與格式不合法分別提示，避免把空白當作有效 key。
2. 保留現行 URL 邊界：僅 HTTP 的 `127.0.0.1` 或 `[::1]`、有效埠、精確路徑 `/v1/audio/transcriptions`，拒絕 userinfo、query、fragment、主機名稱與遠端位址。使用既有環境變數作唯一來源，變更後重啟程式生效。文件說明 server 端 `CODEX_ASR_SERVER_KEY` 必須一致，且不提供密鑰範例值。
3. 設定缺漏或無效時仍可開啟設定與說明，但不得開始錄音或匯入轉錄；顯示可行修正步驟。啟動檢查只驗證本地設定格式，不宣稱 server、登入或網路已就緒，不發送音檔、不啟動 server。
4. 設定檔缺失使用預設值。損壞或不可讀時顯示非敏感的提示並保留原檔，不在讀取時覆寫。設定存檔失敗時保留目前運行設定並告知使用者；不得回報已儲存。保留既有設定與快捷鍵預設關閉的行為。

key 使用環境變數原值，不自動 trim。缺失、空字串或全空白歸類為缺失；其他值長度為 1 至 4096 個字元，只允許 ASCII 33 至 126，包含空白或非 ASCII 字元即為格式無效。實作應拒絕無法放入 Authorization header 的值並以相同安全錯誤提示。server 設定值也須使用相同的有效 key，不在文件或日誌中顯示實際值。

缺少設定檔時以記憶體預設值啟動，不在讀取時建立檔案；首次明確儲存設定時才建立。設定檔損壞、不可讀或讀取後無法寫入時不覆蓋原檔。損壞或不可讀時使用記憶體預設值，顯示警告及檔案修復指引，bridge 設定有效時仍可使用轉錄。成功讀取的設定即使檔案不可寫也可在本次工作階段使用。使用者儲存新設定失敗時回復到儲存前的運行設定並提示失敗；寫入採安全替換，失敗保留既有檔案。

## 錯誤分類

以結構化錯誤類別傳遞至 UI，不以例外訊息子字串判定。介面用繁體中文顯示原因與下一步，不顯示原始 HTTP body、認證資料、音訊內容或逐字稿。診斷只保留安全類別、HTTP 數字狀態及必要時間資訊，不記錄 key、header、原始回應、音檔路徑或內容。未知例外顯示通用訊息。

| 類別 | 條件 | 顯示與行動 |
| --- | --- | --- |
| 設定錯誤 | URL 或 key 缺失、格式無效 | 修正環境設定並重啟，不發請求 |
| 音訊錯誤 | 裝置不可用、檔案不存在、不可讀、空白、格式、時長或大小不符 | 檢查麥克風或重新選檔；不發請求 |
| 連線失敗 | 本機 bridge 無法連線或連線中斷 | 檢查本機 server；可能已送出時警告結果未知 |
| 逾時 | 五分鐘期限到期，非使用者取消 | 提示處理結果未知，可能已傳至雲端 |
| 授權被拒 | HTTP 401 或 403 | 提示檢查本機 REST key 和 bridge 登入，不斷言具體失敗層 |
| 限流 | HTTP 429 | 稍候再由使用者重試 |
| 服務失敗 | HTTP 5xx | 檢查 bridge，稍後重試；結果可能未知 |
| 其他 HTTP | 包含 3xx 與其他 4xx | 顯示安全狀態碼與檢查設定提示；不跟隨 redirect |
| 回應無效 | JSON 無效、超過 1 MiB、缺少文字或空白 | 提示回應無效或無辨識文字，保留原音檔供使用者決定 |
| 已取消 | 使用者取消 | 顯示已取消；已送出的資料無法撤回，忽略遲到結果 |
| 未知 | 其餘失敗 | 通用錯誤與安全診斷，不洩露例外原文 |

## 失敗重試與資料生命週期

- 不自動重試。失敗後提供明確的「重試」與「放棄」；單次只允許一個進行中的請求。重試不得在已取消、成功、放棄或檔案不可用時啟動。若檔案無法讀取，提示重新錄音或選檔，不送請求。
- 每次重試都是新的外送，重新顯示既有雲端同意提示。若前一次可能已送出，提示可能產生重複處理及費用；取消同意不得送出。不能以客戶端取消或逾時推定服務端未處理，也不宣稱冪等。
- 重試使用同一個完整音檔，並重新檢查存在、可讀及大小等限制。匯入檔在每次送出前重新檢查時長與格式；檔案可能已變動，提示使用者並取得同意後才送出。每次請求建立新的 stream、multipart 與取消權杖。
- 錄音暫存只在目前程式工作階段保留供重試。成功、放棄、取消、開始新工作或正常結束時清除程式擁有的暫存檔；清除失敗記錄安全診斷並以既有過期清理作後備。當音檔正被使用時不得由清理程序刪除。程式異常退出後不承諾復原；保留既有超過一天的清理策略。匯入原檔永不由程式刪除或覆寫。
- 轉錄中取消應立即使 UI 離開處理狀態；等待中的請求及遲到成功或失敗不得覆蓋新狀態。重試期間不能啟動第二次重試或新的轉錄。新工作取代舊工作前須先放棄舊音檔。不能把未成功的文字寫入歷史或複製。

UI 狀態與檔案清理分開處理。取消時立即更新 UI 並要求取消請求，但將錄音暫存標記為待刪除，直到該請求及其 stream 已釋放才刪除；未釋放前不允許任何清理程序刪除。正常結束時提出取消並等待資源釋放，最多等待 5 秒；超時則允許程式退出並保留待清理檔案，不宣稱已刪除。後續啟動仍依超過一天的門檻清理；未滿一天則保留至符合門檻後的啟動。失敗後選擇重試時，只有前次請求已結束並釋放 stream 才能重新開啟檔案；失敗後尚未結束時保持重試不可用。清理失敗不得顯示為已清除。

## 驗收

1. 自動測試設定缺失、無效、合法 loopback IPv4/IPv6、遠端、redirect、query、fragment 與無效 key；證明不合法設定沒有發出 HTTP 請求。測試設定檔損壞與不可寫，證明原檔未被覆寫及錯誤可見。
2. 以 mock handler 測試 401、403、429、500、其他 4xx、3xx、連線中斷、逾時、取消、無效 JSON、超大回應和空文字。核對分類、使用者提示及日誌不含測試秘密或原始 body。驗證每次失敗沒有自動重送。
3. 測試失敗後手動重試成功、拒絕同意、音檔刪除或變更、連續點擊、取消後遲到的成功和失敗。核對請求數、每次同意、完整音訊、狀態及不產生過期結果。
4. 測試錄音暫存的成功、放棄、取消、結束、清理失敗及過期清理，並證明匯入原檔未被修改或刪除。測試有使用中的檔案不被清理。
5. 在 Windows 建置並以實際 UI 驗證設定錯誤、啟動修正、錄音與匯入、同意、失敗、重試、取消及關閉。使用受控本機 bridge 驗證完整流程；真實雲端轉錄須由使用者明確同意後另行驗證。記錄 OS、commit、命令、結果與未驗項目，不把 mock 或編譯當作真實轉錄通過。
6. 更新中英文 README 與驗證紀錄，說明設定、錯誤行動、重試與隱私限制。回歸既有匯入限制、單一轉錄、proxy/redirect 禁用、雲端同意及快捷鍵 opt-in。
