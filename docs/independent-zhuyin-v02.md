# 個人注音 IME-001：獨立 Windows 版實作規格 v0.2

範圍是台灣標準注音、整句選詞、個人學習、本機語音；不依賴 Rime、小狼毫或自然輸入法的 DLL、資料表、服務。前一版 0.2.1 是 Rime 設定原型；本文件的 v0.2 是文件版號，不是新輸入法的發布版。延續 [Issue #5](https://github.com/skydreamer0/audio-notes/issues/5) 的安裝回復、草稿、隱私與相容性驗收。

## V12 操作基線：用測試窗分開記錄候選、組字與實際送字

| 情境 | 受測 V12 的行為 | 對新產品的要求 |
|---|---|---|
| 第一聲 | 在空白輸入框打 u 後第一次空白預覽「一」，Enter 才送字 | 音節完成和文字提交是不同事件 |
| 單字 | su3 改選「妳」並送出，連續三次，第四次仍是你、妳 | 孤立單字保持穩定；不把單次改選套用到全域 |
| 句子或局部 | su3 cl3 a87 的候選同時有「你好嗎、妳好嗎、你好、妳好、妳、你」。選「你好」後「嗎」仍可選，最後一次提交「你好嗎」 | 候選必須攜帶文字及涵蓋的音節範圍，不能一選前段就整句上屏 |
| 同音帶前文 | 「我愛你」可先選「我愛」，再改末字為「妳」，最後結果「我愛妳」 | 支援局部修正；鎖定的跨度不能被之後的重算改寫 |
| 相互重疊 | 「研究生」是三音首選。延長至六音後，能選整句「研究生命起源」、前段「研究生」或「研究」。選「研究」後有「生命起源、生命、生」供選 | 自動重算尚未鎖定的音節；同一句文字可能用不同詞界抵達，不用上屏文字倒推詞界 |

原廠 [Windows V12 手冊，附錄](https://dl1.iqt.ai/sw/Going_input_V12_User_Guide.pdf) 把 Tab 切詞、手動增刪詞、顯示同音字分成不同操作。受測狀態按 Tab 會改變候選範圍；未以這次畫面推斷所有模式。

## 原版內部如何配合

Windows 32/64 位元前端 → 服務程式按鍵入口與組字視窗 → 原生模組的鍵盤表及 Predictor → 每個位置的詞候選 → 處理重疊 → 可能再經舊引擎調整 → 候選介面或送字。這是已定位元件的關係示意，不是針對每個按鍵的全程執行軌跡。

對固定 OVIMGoing.dll 樣本 df19ddde…，已用 REA/Ghidra 與比較指令確認其中一個 partition 階段：先為各起點取得候選，以 Unicode 字元數由長到短排列；與後方重疊而後方有更長詞時，重新挑目前候選。保留一段之後略過覆蓋位置。比較器在這一步沒有比較詞頻。同長同音字的順位無法從長度推得，有條件的後處理也可能改變結果。

單字出廠表有 ord；另一個特定詞表查詢按 logProb 降冪。個人資料有命中次數與時間、同鍵最近三筆的查詢；也實際定位到啟發式紀錄的寫入方法。這些不是同一條查詢；沒有證據給出一般選字一律提升幾名或第幾次必定升首。十二個常見測詞在三張出廠表的指定文字欄位都沒有整詞精確命中，原版卻能組出其中若干詞。不能直接把這三張表當完整語言模型。新產品只採可觀察行為、公開方法和自有規則。

## 新產品如何分工

1. **Windows 輸入服務**：自有識別碼，現代標準注音布局。依 [Microsoft TSF composition](https://learn.microsoft.com/en-us/windows/win32/tsf/compositions) 將組字、選字和一次提交放在同一輸入框的編輯工作階段。焦點或文件改變時不把舊結果送往新目標。先 x64 再 x86；兩者均須有安裝、啟用、停用、卸載、回復驗收。安裝不改預設輸入法。
2. **獨立核心**：按鍵 → 未完成音節 → 注音陣列與固定詞界 → 產生跨度候選 → 選整句或局部 → 送字。標準注音採聲調或空白結束音節、Enter 確認、Esc 取消、Backspace 退回；進入候選層才可用選字鍵，數字聲調不能被誤吃。句首或游標位置可選詞。列出未鎖定區段的整句結果與前段選項，重複文字去重；不同跨度不可混成同一項。
3. **公開詞庫與斷詞**：先固定 [小麥注音來源](https://github.com/openvanilla/McBopomofo/tree/1cb01763f09dd72290021b7d880e668c59d02f82)。實際建出 data.txt，過濾特殊鍵後 174,002 筆，SHA-256 6a8beb29f2c5f156e073c1cfdc26b5abbc2f610f815e187b7ec927656adecbd3（本機建置）。整句預設以音節位置為節點、詞為邊，累加詞分數，以動態規劃找最佳切分；同分要有穩定順序。將原版「保留整句與前段」做成自己的候選介面。不得宣稱 V12 使用小麥的演算法。上游程式 MIT，交付詞庫前須核對來源與逐項附帶聲明，不散布 V12 的檔案。
4. **個人學習**：把出廠基礎詞序、當次鎖定、使用者手動加詞、依上下文記憶分成四層。初版孤立單字不自動換首；在非敏感的一般欄位，由使用者啟用後才記錄已提交的明確改選。建議以左側已選詞＋目前讀音為鍵；只存必要詞條，不保存原句。明文規格：同一上下文改選一次只在當次鎖定；兩次不同提交後才在該上下文提供偏好；其他上下文與無前文維持基準。新規則不宣稱等同 V12。支援匯出、移除、全部清空；未送出的選字、取消、程式碼/密碼等排除欄位不得學習。對照 [小麥上下文偏好與時間衰減](https://github.com/openvanilla/McBopomofo/blob/1cb01763f09dd72290021b7d880e668c59d02f82/Source/Engine/UserOverrideModel.cpp) 及 [新酷音 Editor 與自動學詞](https://docs.rs/chewing/latest/chewing/)。
5. **語音**：沿用 Audio Notes 的 WavAudioRecorder、IRecognitionEngine、LocalWhisperRecognitionEngine；可替換辨識器在獨立工作程序執行。測試台已呼叫現有 C# 辨識模組，以 whisper.cpp 1.9.2 加本機 base 模型處理指定音檔，回傳繁體結果。正式版錄音明確開始／停止、暫存清理、取消、錯誤回復；辨識結果先預覽，允許修改，再選擇接到原組字或草稿。不得模擬 Enter 送出聊天，不在焦點已變時自動插入。原 Audio Notes 會記錄辨識歷史；正式整合須增加預設不保存的選項，不能照搬。模型訓練與輸入法選詞記憶分開。
6. **草稿與資料邊界**：只復原產品自己持有、已選擇保存的草稿；使用者可刪除。錄音或辨識失敗不清空草稿，其他程式尚未送出的輸入不保證能復原。測試台目前是記憶體草稿，非正式持久儲存。

## 交付順序與驗收

- 核心：上述五組原版案例，加上破音字、同長異詞、未知詞、繁簡同音、插入／刪除／取消、手動詞界和左右文對照。加入獨立於既有測詞的評估集，報整句準確率、每百字修正次數與候選延遲（揭露機器、句長、P50/P95），不得用五組樣本證明整體準確率。
- 語音：以固定中文 WAV 驗證現有辨識器與預覽，另驗空音檔、無麥克風、取消、切換視窗、保留草稿和確認後只插入一次；真人錄音獨立驗收。
- Windows：從系統輸入法清單選到自有識別碼；在記事本、瀏覽器與 Codex 的受控草稿驗組字中／上屏後／關窗。只有在無小狼毫服務或不載入 librime 的情境實際打字通過，才能稱獨立系統輸入法。受保護欄位、跨處理程序位元數、無障礙、焦點移動及移除後不破壞舊輸入法都要測。
- 現況：有獨立的實驗視窗，能對照注音和離線音檔；產品版 TSF、持久學習與跨應用語音尚未交付。工程實作交接到既有 Issue #5。
